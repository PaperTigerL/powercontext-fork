# 技术说明 · 端侧迷你知识库（seekdb × 阶跃星辰）

## 1. 应用与架构

一个跑在 Chrome/Edge 最新版的迷你知识库：导入文本 → **浏览器本地**完成向量化 → 写入 **seekdb** → 查询时本地生成查询向量 → **seekdb 执行向量+全文混合检索**并返回排序结果。全程不调用任何云端推理 API。

```
浏览器（Vite 构建的静态应用）
  ├─ Transformers.js + 本地打包 ONNX 模型（bge-small-zh-v1.5，512 维）
  │    文档/查询向量均在本地计算；优先 WebGPU(FP16)，不支持自动降级 WASM(INT8)，界面实时显示当前后端
  └─ fetch /api/*  →  本地 Node 服务（仅传输与参数校验，不做事检索）
                        └─ seekdb-js → seekdb（127.0.0.1:2881）
                              集合 edge_kb：向量索引(hnsw, cosine, 512) + 全文索引(ik 中文分词)
                              混合检索由数据库执行：query(全文) + knn(向量) + RRF 融合
```

## 2. 端侧推理与模型量化

- **模型**：`bge-small-zh-v1.5`（中文检索向小型模型，512 维输出），采用社区预转换的 ONNX 版（Xenova/bge-small-zh-v1.5），随应用打包在 `web/public/models/`，运行时不访问外网。
- **量化方案**：同时提供两套权重，前端可选——**FP16**（WebGPU 默认）与 **INT8**（WASM 默认，ORT 动态量化）。
- **体积对比**（实测，`npm run size-report`）：

| 精度 | 文件 | 体积 | 相对 FP16 |
| --- | --- | --- | --- |
| FP16 | onnx/model_fp16.onnx | 45.30 MB | 1.00x |
| INT8 | onnx/model_quantized.onnx | 22.90 MB | **0.51x（压缩 1.98x）** |

- **质量变化**（48 篇中文文档、12 条查询，Recall@10，`npm run bench`）：

| 精度 | Recall@10 | 说明 |
| --- | --- | --- |
| FP16 | 1.00 | 基线 |
| INT8 | 1.00 | **无可测质量损失** |

INT8 权重体积减半、检索质量不变，因此默认端侧配置为 WebGPU-FP16 / WASM-INT8。

## 3. 推理后端与降级

按 `webgpu(fp16) → wasm(int8)` 顺序尝试初始化（Transformers.js `device`/`dtype`），失败即降级；页面徽章实时显示 `WebGPU · FP16` 或 `WASM(降级) · INT8`，核心流程在两种后端下均可运行。

## 4. seekdb 存储与混合检索

- **schema**（seekdb-js `Schema`）：全文索引显式使用 **ik 中文分词**（默认 space 分词对中文无效）；向量索引 hnsw/cosine/512；`embeddingFunction=null`——向量由端侧生成，服务端不做嵌入。
- **写入**：`collection.add({ids, documents, embeddings, metadatas})`，随后 `refresh_index()` 刷新向量索引，保证增量导入后新文档立即可检索（已实测：写入 3 条后立即检索命中）。
- **混合检索**：`collection.hybridSearch({ query: { whereDocument: { $contains } }, knn: { queryEmbeddings }, rank: { rrf } })`，两路候选与 RRF 融合**全部在数据库内完成**，客户端不分别取结果自行拼合。

## 5. 性能实测（`npm run bench`，Node/WASM/CPU，i7-10750H）

| 指标 | INT8 | FP16 |
| --- | --- | --- |
| 模型加载 | 342 ms | 287 ms |
| 单文档嵌入 | 10 ms | 12 ms |
| 混合检索（平均） | 20 ms | 12 ms |

优化点：模型文件本地打包 + `useBrowserCache=false`（避免 OPFS 缓存首次开销）；嵌入按批处理（batch_size=8）；检索走数据库索引（hnsw + ik）而非全表扫描；写入后一次 `refresh_index()` 而非逐条刷新。浏览器 WebGPU 后端下嵌入延迟预期进一步下降（本机无 GPU 环境，未测 WebGPU 数值）。

## 6. 复现

```bash
npm install --legacy-peer-deps
docker run -d -p 2881:2881 --name seekdb oceanbase/seekdb   # 或已有 seekdb 服务
npm run download-models     # 模型打包（hf-mirror）
npm run gen-corpus          # 演示语料
npm run build && npm start  # http://127.0.0.1:8787
npm run bench               # 全链路基准与质量对比
```

测试环境：Windows 11 / Node 22 / seekdb v1.4.0.0（docker）；判题复现建议使用 Linux + Chrome/Edge 最新版。
